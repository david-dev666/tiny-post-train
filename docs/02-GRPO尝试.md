# GRPO 这一轮：负结果与不确定边界

阶段 3「GRPO + 可验证奖励」的一次完整尝试（IF-RLVR，AI2，arXiv 2507.02833）。

**一句话**：主指标 0.0pp 提升（120/200 → 120/200），但**这轮到底「失败了」还是「没测对」，现有数据还判不了** —— 缺 IFBench。

数据来自服务器实测（`outputs/grpo-4b-ifrlvr`），评测产物未入库（`evals/results/*.json` 不进版本库），下面只留结论与归因。环境是单卡 **RTX 5090 32G**（2026-10-06 换机后；主表那批结果出自 4090 24G），训练跑在 `vllm` 环境（trl 1.14.1 + vllm 0.30 + transformers 5.18，colocate 模式），为什么这么选见 `notes/workflow.md`。

## 一、主因：奖励形式打不到主指标真正的缺口（结构性，能确定）

这是最硬的一条，且**在实验前就注定**。

主指标 8 类里，分值全压在两类上：

| 类别 | 通过 | 说明 |
| --- | --- | --- |
| 数值约束 | **0/25** | 要求「输出就是一个纯数字」 |
| 长度约束 | **2/25** | 要求「恰好 N 字 / N 行」 |
| 其余 6 类 | 118/150 | 代码约束、禁忌词已接近满分（25/25、24/25） |

也就是说：**200 题里 102 分来自已经饱和的 6 类，50 题只拿到 2 分**。

而这 50 题的失败方式被 `flipped_by_junk_tail` 直接指认了 —— `num-01~num-20`（20 条数值题**全部**在列）、`len-g03/g07/g09/…`、`lang-wc-1~5` 全在列。**它们是输出了正确答案之后，收尾多吐一个乱码 token**（`72` → `72 לחלוט`），把「纯数字」这个约束撑爆了。

GRPO 的奖励是**「通过约束的比例」**，它是一个**整条序列的函数**；而乱码尾的靶心是 `<|im_end|>` 那**一个 token** 的 logit（项目已量化：排第 4、只差 0.13 nats）。序列级信号落不到单点上 —— **GRPO 结构上就修不了这个缺口**。

这不是新结论，是项目第 **14** 次验证同一件事（SFT 侧 6 + DPO 5 + RFT 2 + GRPO 1）。

**旁证**：`junk_tail` 从 178 → **184（反而多了 6 个）**。GRPO 不但没改善收尾，还略微加重。

## 二、次因：更新幅度太小，模型基本没动（能确定，但不是主因）

| 证据 | 值 | 含义 |
| --- | --- | --- |
| `kl` | 均值 0.0009、max 0.0032 | 策略**几乎没偏离起点** |
| 主指标 | 120 → 120 题 | 一道都没跨过门槛 |
| `junk_tail` / `trimmed` | 178→184 / 154→150 | 全在噪声内 |
| 分类别 | +1（格式）−1（语言） | 零和 |

`lr = 1e-6` 是照论文取的（论文是全参 8B 用 5e-7），但**这个脚本用的是 LoRA** —— LoRA 的常见 lr 比全参大 10~100 倍。所以「模型没动」有参数依据。

但要诚实说：**即使把 lr 调大，主指标大概率还是不涨**，因为瓶颈在第一节（乱码尾）。lr 只是让这轮更「没动」而已。

## 三、还有两个拖累项（能确定，量级较小）

1. **约 1/3 的样本没有梯度**：`frac_reward_zero_std` 全程稳定在 **0.32~0.34**，即 1/3 的 prompt 组内 8 条全对或全错 → 优势为 0 → 这些数据白喂。
2. **数据量与空间**：1500 条 prompt（论文用 60k~100k）；且起点在这些英文约束上已有 0.23 通过率，可提升的空间本就有限。

## 四、最大的不确定性：尺子可能拿错了（未测，无法判定）

这一条必须放在这里，因为它决定了上面所有结论的**适用范围**。

| | 训练侧 | 评测侧 |
| --- | --- | --- |
| 语言 | 英文约束描述（IFEval 25 + IFTrain 29） | **中文**模板题 |
| 约束类型 | 54 种，其中 29 种是 IFBench 全新设计 | 自建的 8 类 24 种规则 |
| 用途 | 训练 | 同时也是项目历史基线 |

IF-RLVR 的论文目标是**「精确指令遵循的泛化」**，它的标准度量是 **IFBench（58 个全新约束、299 条 held-out、WildChat 来源）** —— 而 IFBench **我们一条都还没跑**。

而论文本身有个直接相关的发现：**模型会 overfit 到 IFEval 的 25 个模板**（2B 模型就能在 IFEval 上拿 80+）。我们的训练数据里正好有这 25 个模板。也就是说，训练集 reward 涨到 0.319，**有可能涨的是「模板记忆」**，而这恰恰只有 IFBench 能识破。

所以现在的状态是：

| 问题 | 能不能回答 |
| --- | --- |
| 主指标涨了吗 | 没涨（0.0pp） |
| 乱码尾改善了吗 | 没改善（184，还多了 6） |
| 其他能力退化了吗 | 没退化（MMLU / GSM8K / HumanEval 全在抖动内） |
| **这轮 GRPO 学到东西了吗** | **答不了 —— 缺 IFBench** |
| lr 太小是不是主因 | 只能说「确实没怎么动」，但不能说是它导致主指标不涨 |

## 一句话归纳

**失败的直接原因是「奖励形式打不到瓶颈」—— 主指标 50 分的缺口卡在收尾那一个 token 上，而序列级奖励天然够不着它；这也解释了为什么训练集 reward 涨了 39% 而评测一题未动。** 但**「这轮方法本身无效」这个更强的主张，现有数据不支持** —— 因为用的是被乱码尾污染的、且与训练分布不同源的中文尺子。
